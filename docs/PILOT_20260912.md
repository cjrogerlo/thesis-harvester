# Local real-paper pilot — 2026-09-12

This is a four-document convenience sample of locally available Apollo theses, not a representative archive benchmark. Source PDFs, manifests, excerpts, page images, models and search databases remain in ignored local output/cache directories. No paper content is published with this report.

## What ran

- Copied four stable local PDFs and a 6,062-row download manifest into an isolated pilot directory; active downloaders were not changed.
- Matched **4/4 PDFs**, with UUID, original/stored filename, recorded size and SHA-256 verification; **0 binding errors**. Two filenames required the recorded sanitized download name rather than the original remote name.
- Extracted **825 physical PDF pages** using pypdf 6.8.0 and `cl100k_base` chunking, yielding **1,493 chunks**. Two documents were mechanically ready; two remained `needs_ocr` due to low-text candidate pages. These candidates include possible blanks/figures and do not establish the archive's scan proportion.
- Built an explicit review-inclusive local FTS5 index: **4 documents, 1,479 chunks**, excluding **14 low-text/unanchored chunks**. This leaves source processing statuses unchanged.
- All four records carried explicit `all-rights-reserved` metadata. They were not reclassified as commercial-training eligible.
- Ran Docling **2.126.0** locally on **four selected original pages**: two inline statistical-numerical pages and two dense, continued table pages. Model weights were downloaded, and no hosted inference endpoint received the PDFs.

## Retrieval observations

Queries for FAMIN/T-cell priming, arterial stiffness/cardiovascular prediction, and REGENIE/conditional analysis returned paper/page citations. REGENIE results included physical pages 61, 62 and 86 in the relevant genetics thesis. Returned page anchors are physical PDF indices, not printed page labels.

Real queries exposed two implementation issues that were fixed: repeated chunks on the same page crowded results; title-only matches could rank tiny unrelated headings as evidence. Search now deduplicates document/page ranges within its bounded candidate pool and requires matches in chunk content. Broad terms can still rank a cover, contents page or reference list highly. Heuristic `body` labels were also insufficient on these documents. This pilot does **not** demonstrate robust literature question answering, semantic recall, or reliable body/reference separation.

## Structured extraction review: not accepted for training

For the numerical passage, Docling preserved the two-page provenance, but treated inline statistics as ordinary text: superscripts such as powers of ten were flattened rather than reliably serialized as LaTeX. Broken ligatures remained in some words. There were seven unique text blocks, including one spanning both pages, and no recognized formula blocks. Merely enabling formula enrichment did not repair inline mathematics.

For the two table pages, Docling emitted two HTML tables and preserved some `rowspan` structure. The warm-cache two-page review took **43.964 seconds** on this host, including process/model initialization. This is a single timing, not a throughput estimate.

Visual comparison with the original second table page found concrete row-association errors: the end of a sample-size expression from row 15 moved into row 16, and the beginning of an outcome value from row 17 moved into row 16. Split words and page numbers classified as body text also remained. These failures make numerical table output unsuitable for unattended training acceptance.

The review output is explicitly partial, records source SHA-256 and page ranges, and never enters the ready corpus ledger. Keep the original page images and Docling item JSON for a later extractor comparison. The report records observed failures; it is not a complete character/cell-level accuracy annotation.

## Validation and next acceptance work

The final automated suite discovered **41 tests: 40 passed, 1 skipped** (Poppler unavailable). The model pilot above was separate from mocked adapter contract tests. See [VALIDATION.md](VALIDATION.md) and [RESEARCH_WORKFLOW.md](RESEARCH_WORKFLOW.md).

Before scaling structured extraction, add held-out real scans, two-column articles, displayed equations and figure/caption cases; annotate expected formulas and table cell associations; compare extractor versions against the same source hashes. This pilot supports a working source-bound corpus baseline and local cited retrieval, while showing that structured transcription quality remains unresolved.
